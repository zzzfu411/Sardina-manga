# Sardina 0.4.0 复审修复交付记录

依据：[体验与功能逻辑复审](2026-09-26_体验与功能逻辑复审.md)与[详细执行计划](2026-09-26_复审修复执行计划.md)。从 `299d21e` 的 0.3.0 基线推进，以 Goal 跟踪 R01–R12；阅读、数据、交互三个 Agent 分工实现，协调者负责服务、交叉审查、整体验收和交付。以下记录的是当前代码的行为和已完成验证。

## 问题与实现对应

| 项目 | 修复后的行为 | 主要实现与验证 |
|---|---|---|
| R01 坏图重试 | 解码失败使对应 Blob 失效；手动重试先更新图片请求，再按需刷新清单。同 URL 不反复读取坏缓存，不清空其他页。 | `image-loader.js`、`reader.js`；合成坏图→点击一次重试→可解码好图，总请求恰好 2 次。 |
| R02 空清单 | 缓存及健康统计之前检查非空列表、URL 与图片域名。无效结果不算成功；“重试本章”主动刷新清单。合法空搜索语义保留。 | `server.py`、`reader.js`；空/异常清单与再次恢复的单元/API 测试。 |
| R03 本地章节 | 在线目录删章后仍保留下载资产入口；从下载管理与原深链接均可读取本地图片。孤立本地条目不猜测前后章、不写入共享在线目录。 | `download-store.js`、`reader-model.js`；真实 IndexedDB 验收，远程清单和图片请求均为 0。 |
| R04 删除优先 | 阅读会话携带删除代次；退出、隐藏或后台目录保存不能推翻之后的删除。用户重新阅读、收藏、撤销或导入仍可主动恢复。 | `library-store.js`、`app.js`；真实双标签删除与重新阅读，另有排队写入、删除后重加、迟到目录的确定性竞态测试。 |
| R05 推荐反馈 | 按操作在 Web Lock 中合并偏好、曝光、忽略/撤销与计数，清空使旧代次操作失效；跨标签同步界面。点击时捕获原漫画，避免同步换卡后开错作品。 | 推荐反馈、模型与 UI 模块；真实双标签偏好/曝光/清空、锁排队、清空代次和同步换卡测试。 |
| R06 当前页优先 | 图片请求区分当前页、预读、下载与封面。服务总并发 8，后台最多 6，为当前页保留 2；排队合并任务可提升优先级，后台按可用容量先进先出。阅读时暂停未完成封面，关闭后恢复。 | `request_budget.py`、`image-loader.js`、`cover-pause.js`；慢封面、共享请求提升、公平性、超时释放、绝对地址封面与快速开关测试。 |
| R07 可读性反馈 | 封面和正文健康分开；成功后仍保留近期失败，局部排队超时不归咎于源站。推荐阅读分别记录失败与恢复，同会话去重。 | `source_health.py`、阅读/推荐模块；浏览器实测开始阅读 1、失败 1、恢复 1；近期失败继续影响推荐排序。 |
| R08 返回行为 | 应用内关闭阅读与详情返回已有父历史记录；深链接使用替换回退；换章保留所属阅读层。 | `route-history.js`、`app.js`；发现→详情→阅读→关闭不增加历史，浏览器前进仍能重开详情和阅读。 |
| R09 空状态 | “查看全部”清除含“只看收藏”在内的筛选；“去找漫画”回到首页并聚焦可见搜索框。 | `app.js`；真实浏览器验证筛选恢复与发现页空书架入口。 |
| R10 可逆操作 | 可取消收藏而保留进度；移出书架有 10 秒撤销窗口，悬停/聚焦时暂停计时。 | `app.js`、`library.css`；取消收藏、移出、撤销后的进度保留验证。 |
| R11 大列表 | 书架最多 48 本/页，详情和阅读目录最多 80 章/页；全文查询覆盖未呈现条目。阅读目录打开前不创建条目，当前章定位与键盘导航有效。 | `page-window.js`、`app.js`、`reader.js`；1,000 本与 2,000 章的节点、搜索、焦点和窄屏验证。 |
| R12 失败诊断 | 检查开始、各步结束及失败退出均更新汇总；场景标注阶段，失败保留截图、DOM、控制台、请求失败与 trace。 | `scripts/check.py` 与浏览器场景；故意制造坏图后断言失败，退出码 1，完整证据已检查。 |

实现时另处理了空图片字节、损坏健康历史、Future 建立而排队尚未开始时的共享请求提升、被动保存覆盖待写进度保护等边界。没有增加运行时框架或依赖。

## 追加发现：本地连接突发丢失

首轮完整回归通过后，扩展规模场景时出现一次 `/library-store.js` 连接重置，页面因此没有完成初始化。新诊断工具保留了具体请求、阶段、DOM 与 trace：[原始失败](../output/repair-20260926/scale-verification/reaudit-failure.json)，没有通过覆盖失败记录来忽略问题。

独立临时端口使用真实 Handler，对比 Python 3.12 默认待接收队列 5 与队列 64：6 连接、10 轮时，默认队列出现 1 次重置，扩大后 60/60 成功；8 连接、5 轮时，默认队列每轮失败 2–3 个，扩大后 40/40 成功；24 连接、5 轮时，默认队列每轮失败 17–19 个，扩大后 120/120 成功。失败都在 Handler 接到请求前发生。证据：[突发对照](../output/repair-20260926/connection-probe/results.json)、[6 连接对照](../output/repair-20260926/connection-probe/six-connections.json)。

生产启动与检查入口现在共用 `SardinaHTTPServer`，待接收队列为 64，另有暂停 accept 循环时 12 个完整模块请求的行为回归。漫画源元数据与图片请求仍由原业务并发预算限制。该探针复现并修复了同类本地突发连接丢失，不能据此认定所有历史超时均为同一原因。

## 数据与兼容性

- 下载数据库仍为 v2，原图片、共享目录及任务保留；没有清空或重建用户数据库。原先已下载的孤立章节仅在读取时补入本地目录视图。
- 书架沿用 v2 逐本记录与原键名，新增 `deletionEpoch`；旧记录、旧删除标记和书架 v1/v2 备份可读。明确操作可建立新阅读会话，旧会话不能在删除后重加时越过保护。
- 推荐仍用 `revyunman.recommendations.v1` 键，正常写入时将内容升级为 `version:2`，保留旧偏好、曝光、忽略与 6 个已有计数；新增恢复计数、偏好/撤销时钟和清空代次。损坏记录会保留，只有明确清空才重建。
- 升级后须刷新所有已打开的 Sardina 标签，才能让所有写入者使用新的合并与删除保护。旧版源码只接受推荐 v1，也不保留删除代次，**回退源码不等于回退数据**。没有自动执行降级迁移。
- 跨标签原子合并在支持 Web Locks 的浏览器中成立，本轮 Chromium 已验证；无 Web Locks 的环境采用同步读改写降级，不能承诺跨进程同时提交一致。
- 正文与封面健康现在分开统计。图片健康记录的是 API 观测（包括缓存命中），最近窗口为最多 32 次且不超过 15 分钟，并非全网源站成功率；客户端解码失败另入推荐阅读事件。

## 本地交付

版本已同步到 Python 项目、Node 项目、锁文件与 HTTP 服务标识（0.4.0 / Sardina 0.4）。2026-09-26 已通过项目启动器重启本地服务；首页、配置和 5 个关键模块共 7 条检查均返回 200，服务标识为 `Sardina/0.4`、模式为 `native`：[服务确认](../output/repair-20260926/service-smoke.json)。可打开 <http://127.0.0.1:8765/>，刷新所有旧标签以加载新代码。运行日志仍在 `output/runtime/sardina-server.log`。

本轮没有发布到外部服务，GitHub Actions 尚未远程执行；当前工作区代码、计划、审计与交付记录为交付内容。线上源实时可用性和真实移动设备长时间阅读仍属于后续抽样验证范围。
