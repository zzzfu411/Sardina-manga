# 新解包源接入：Intent → Spec → Impl

## Intent

将用户第三轮 APK / 规则提取结果接入现有云漫，保持原版 12 源及已接入 6 源不回退。以搜索、作品目录和真实首图验证决定启用，不把新发现的域名或规则条数当成可读漫画源数量。

## 初始审计

- `round2-octopus-vomic.json` 包含你搜 v185 的 95 条规则，以及章鱼的 4 条源目录记录。规则存在同源镜像、重复入口、静态网页、页面脚本、特殊请求参数及失效域名，不能原样作为现有 Python 适配器使用。
- `round2-sunday-lingyue.json` 已记录 Sunday Webry 正常网页 GraphQL 的搜索、作品及免费章节图片协议；其 App 原生接口不能代替网站接口。
- `round2-tachiyomi-protocols.json` 还包含泰拉记事社、NamiComi、Happymh、漫画人等协议线索，需要核对当前入口、分页与正常访问权限。
- 漫客栈、再漫画、拷贝等属于已有源的补充资料，不重复注册；官方 App 的失效 API、元数据平台及视频规则不计作新漫画源。

## Spec：完成条件

1. 新资料逐条入清单，有出处、入口、适配状态和原因；99 条规则不得因失败而悄悄丢失。
2. 每个启用源实现统一搜索、详情、章节图片契约，输出真实作品身份及完整目录；分页未完或受限不得假装成功。
3. 图片域名与 Referer 按源登记；只做正常公开访问，源站的登录、付费或配额限制清晰反馈。
4. 原始规则和远端脚本不在应用启动、搜索、阅读时直接执行；正式运行不依赖 APK 或 `output/` 目录。
5. 对拟启用的源逐个验证：普通作品搜索 → 同作品目录 → 一章图片元数据 → 真实首图经本地代理完整解码。只取必要样本，不保存漫画图片。
6. 产品中可以查询接入状态；只有正式接入的源参与聚合搜索，重复资料及未接通候选不放进搜索队列。
7. 保持旧源、源覆盖提示、失败隔离、书架与阅读进度；受控测试与真实浏览器验证后更新用户的 8765 服务。

## 实施计划

| 阶段 | 工作 | 验收输出 |
| --- | --- | --- |
| M1 清单 | 逐条审计 95 + 4 条资料；识别已接入、重复、受限、待适配 | 99 条审计清单及运行时精简目录 |
| M2 API 适配 | Sunday Webry、泰拉记事社 / NamiComi 独立核验与实现 | 独立适配器、分页/身份/权限测试、真实链路证据 |
| M3 网页适配 | 按现有规则选择可实测的普通网页源，兼容能证实的同类结构 | 网页适配器及真实样本；其余保留明确状态 |
| M4 应用集成 | 源注册、图片代理、源目录查询与筛选 | 可在云漫直接搜索阅读，不重复注册已有源 |
| M5 验收 | 完整回归、每个新增源的应用 HTTP 链路、桌面/手机浏览器 | 验收记录、准确启用数量、剩余边界、8765 更新 |

API、网页规则、源审计由三个 Agent 并行推进，主 Agent 负责整合、源目录体验及最终验收。以下为完成后的实现与验收记录。

### 与原始规则的差异

- 不把 XPath、JavaScript 表达式、Cookie 字段或 APK 内容直接送入运行时。将已经证实的协议写成独立 Python 适配器，只登记经过检查的页面入口和图片域名。
- Sunday 在取得图片前读取正常网页的章节权限与身份。受限章节明确提示；GraphQL 分页循环、缺页和部分错误不会返回假成功。
- 泰拉使用公开迁移后的 `comic.hypergryph.com`。NamiComi 使用当前网页的 `title` 搜索参数，旧插件参数已经失效；保留完整分页及各译本的自然章节顺序。
- 四个网页源按当前真实 HTML 重写解析器。独立复核发现并修正了“同域跳转后错书/错章”和“解析缺项却当作完整结果”的缺口；验证 canonical / 页面 ID、已声明的总数和正文图片节点。网站没有声明总数的部分不伪造完整性证明。
- 新图片走已有的同源代理及阅读器，不产生另一套书架或进度存储。

### 源资料目录

页头新增“源目录”：保留 95 条你搜规则、4 条章鱼资料、29 个 Tachiyomi 插件和 9 份重点协议记录，共 **137 条资料**。同一站的多份资料会对应同一个实际搜索源；只有已注册的 25 个适配器参与搜索。目录支持名称 / 域名与接入状态筛选，区分已接入、重复入口、暂不可用、待适配。

运行时只读取随应用交付的 `client/source_catalog.json`，不依赖 APK、提取文件夹或 `output/`。`scripts/build_source_catalog.py` 是离线开发工具，检查 99 条规则不丢不重，再生成公开文本清单；它不会启用源。

### 保留的边界

本次没有宣称“提取的全部来源均已可读”。连接失败、需要单独适配或尚无完整验证的候选仍在目录中明确标记；Happymh 当前入口 TLS 连接失败，漫画人仍只有待验证协议。原版源此前的拷贝限制、Komiic 配额及歪歪真实图片验收缺口没有因新增来源而自动消失。

免费 / 登录 / 付费权限由源站决定。上述真实验收只证明所列样本在验收时可用，不代表该源全部作品或所有网络环境永久可用。日文与国际站的搜索也遵循源站支持的作品名和语言。


## 最终清单与验收

99 条你搜 / 章鱼规则的最终分类：已接入 7 条（本次新增 4 源、沿用已有 3 源），重复入口 5 条，暂不可用 23 条，待适配或尚未完成验证 64 条。已对 69 条你搜规则进行有界公开搜索探测，并对 4 条章鱼记录取得入口元数据；其他记录保留静态审计原因。详情与探测证据位于 `vomic-audit.json`。

137 条产品目录资料合计：已接入 10 条、重复入口 20 条、暂不可用 25 条、待适配 82 条。这是**资料记录分类**，不是 137 个独立漫画源，也不是 25 个故障源；同一来源可能同时出现在规则、插件及协议记录中。实际聚合搜索队列始终为 25 个独立源。

验证结果：

- 全量 Python 回归 **259/259**，前端回归 **44/44**；最终清单生成后，目录不丢条目 / 不误启用的 3 项测试再次通过。
- 新增七源应用 HTTP 真实链路 **7/7** 通过。四网页源身份 / 完整性修复后，又在更新后的 8765 服务重新取得真实目录与章节图片元数据，数量保持一致；未重复下载正文图片。
- 独立 Agent 复核源目录的计数、文本展示与异步关闭；另一个复核阶段发现的错身份和静默缺项问题已修复，并通过变异回归及真实 HTML 回放。
- 真实浏览器通过源目录名称 / 状态筛选、空结果、320 像素页头与 393 像素对话框布局；修正了搜索框消耗第一次 Escape 的行为，关闭后焦点返回“源目录”。
- 浏览器中 NamiComi 详情显示 54 条带语言的章节，第一章阅读器显示 9 页；桌面和手机布局已目视检查。此项界面验证使用真实目录和图片元数据、**合成正文图片**，与上面的真实图代理解码证据分别记录。
- 本地 **8765** 服务已更新，`/api/sites` 返回 25 源，`/api/config` 原版身份覆盖 12/12，`/api/source-catalog` 返回 137 条完整资料。书架及进度仍使用现有浏览器存储。

可查证文件：`output/apk-round2-integration/deployment-validation.json`、`integration-validation.json`、`vomic-integrity-regression.json`；界面截图位于 `output/playwright/apk-round2-*.png`。源站后续变动应通过相应适配器修复，不直接执行新导入的规则脚本。
