# 原版源覆盖与《富家女姐姐》搜索漏检

**后续复核：** 本文记录补源当时的结果。最新逐源验证见[全源覆盖复核](2026-09-21_全源覆盖复核.md)：公开清单 12/12 已登记，但只有 9 个源取得本轮真实图片样本解码证据；拷贝受限、Komiic 配额及歪歪真实图片验收仍需分别处理。

## Intent：完整覆盖按原版源身份验收

用户指出：原版能准确搜索到《富家女姐姐》，本地不能。期望是补齐缺失能力，并查明差异；不能用新增源的数量或返回候选条数替代原版覆盖。

## 审计：漏了唯一准确命中的源

2026-09-21 同关键词实测，证据位于 `output/source-parity/`。只对标题、源 ID 和目录做统计，不以封面相似度或模糊标题认定同一本书。

|---|---:|---:|

| 搜索返回候选 | 262 | 440 |
| 准确标题命中 | 1 | 0 |

原版命中的作品 ID 为 `3872`。本地相似结果《富家女120》不是该作品。将原版准确标题记录交给现有前端模型，可以得到 100 分准确命中和唯一主结果，因此本次没有降低相关性阈值、强行合并相似书名或添加错误别名。

根因分为两层：

1. `client/providers.py` 未注册 `comicbox`；兼容模式也显式从原版列表过滤它。新增的 6 个 APK 源没有填补这个来源缺口。
2. 歪歪图片地址并非普通 JPEG：需要获取二进制分片，解密、恢复头部、根据二进制内的书籍与页码信息重排。此前整条来源因图片链路未完成被停用，却仍用“17 个源”描述进展，未另验原版覆盖。旧研究文档“12 源已端到端打通”也已更正。

## Spec：本轮验收条件

1. 按原版实时 `/api/sites` 的源 ID 集合比对，缺失集合为空。总源数、新增源数与原版覆盖数分别记录。
2. 默认原生模式和云漫兼容模式均保留 `comicbox`；搜索能准确命中指定标题。
3. 搜索和详情只解析对应主体，目录去重且保留源站顺序，不混入推荐与广告；受限或失效页面不伪装成空成功。
4. 章节逻辑图片携带当页缓存版本、可选主机及 manifest；代理完成解密重排，封面也走相同还原流程。
5. 图片分片地址及重定向限制在源 CDN 范围，错误可重试；限制分片大小、像素数量、解码并发及缓存体积。
6. 保留此前 APK 源、搜索分组及阅读进度行为，新增固定回归防止再次漏源。

## Impl：修复范围

- `client/comicbox.py`：HTML 搜索、书籍元数据、目录和章节逻辑地址适配，不执行上游脚本。简介暂留空，不编造；图片版本从 HTML 获取。
- `client/comicbox_images.py`：实现源站公开脚本的 AES-CBC/PKCS7、二进制头恢复与条带重排。`break_2` 分别解密后合并；`break_avif` 与受支持的 v3 manifest 先合并再解密。书籍与页码以二进制头为准，封面同样还原。
- `client/providers.py`、`server.py`：恢复源注册及兼容模式列表，按 CDN 分流图片代理；图片错误保持失败状态，不返回损坏图片冒充成功。
- `client/source_coverage.py`：增加原版 12 源参考清单和在线比较命令，缺源时退出码非零。页面显示总源数及原版源覆盖；说明核对日期，不将登记情况称为实时可用性。
- `tests/fixtures/source-parity/rich-sister-titles.json`、搜索与应用回归：准确标题来自缺失源时仍为首要结果，不把《富家女120》并入该书。

图片管线另有合成图测试；真实漫画图片未在本轮下载、展示或保存。算法实现不能替代真实图片目视验收。
