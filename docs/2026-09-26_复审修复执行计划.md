# Sardina 复审修复执行计划

依据：[2026-09-26 复审报告](2026-09-26_体验与功能逻辑复审.md)。基线：`299d21e`，现有 593 项单元/API 测试与三组浏览器回归。本计划按 Intent → Spec → Impl → Verify 推进，Goal 覆盖 R01–R12 的实现、整合验证与交付。

用户意图是稳定阅读、保留下载和明确操作、提供可预测的简单界面。保留 Sardina 手绘品牌、25 源入口、现有地址与存储迁移兼容性。长期跨设备同步、完整离线应用壳和推荐模型训练分别列入后续规格，不作为本轮修复的隐含依赖。

## 分工与依赖

| 工作包 | 负责人 | 独占修改范围 | 依赖 |

| B 数据与推荐反馈 | Data Agent | library-store.js、recommendations-feedback/model/ranking.js、recommendations.js、对应单元测试 | 向 UX Agent 提供进度会话保护与推荐同步接口 |

| D 服务与验收 | 协调者 | server.py、client/source_health.py、新资源调度模块、Python 测试、scripts/check.py、tests/browser/、文档与版本 | 整合 A/B/C；固定浏览器场景在接口稳定后收口 |

共享目录直接协作；每包只修改自己负责的文件，接口改变先沟通。各 Agent 先做定向检查，协调者最后执行一次完整回归；出现新失败才增加相关检查。保留审计探针作为修复前证据，正式验收加入受版本控制的固定场景。

## 规格与验收矩阵

| 项目 | 实施细节 | 必须通过的行为验证 |
|---|---|---|
| R01 坏图重试 | 加载器可精确失效；重试区分刷新地址与强制获取字节；解码错误不反复命中坏缓存，保留并发与请求合并 | 同 URL 首次坏图、再次好图，一次重试成功；其他已读页不重下 |
| R02 空清单 | 服务在写成功缓存/健康之前校验清单；显式整章重试绕过旧结果 | 空结果不缓存成功，第二次恢复；合法空搜索仍算无匹配 |
| R03 本地入口 | 共享在线目录与下载资产独立；恢复下载章节时补足本地条目，不猜测替代章节 | 源站目录删章后，下载管理与深链接仍可离线读已存页；导航不会错误跨序列 |
| R04 删除优先 | 阅读会话携带开始时的删除代次/版本；自动保存不能复活之后删除的记录；显式重新打开可创建新记录 | 两标签删除后关闭、隐藏或 pagehide 不复活；再次主动打开正常保存 |
| R05 推荐并发 | 偏好、排除/撤销、曝光、计数明确合并；同步外部写入；清空具有独立代次 | 曝光不覆盖关闭偏好；并发排除/撤销一致；清空不被旧会话恢复 |
| R06 阅读优先 | 请求标明当前页/预读/下载/封面；服务保留前台额度，后台有界、公平排队并超时退出 | 慢封面占用时当前页仍进入服务；总并发上限保持；无永久后台饥饿 |
| R07 可读性 | 封面与正文健康分开；近期失败保留；首图解码失败/恢复进入推荐会话指标；未知不算成功 | 封面成功不洗掉正文失败；坏图记失败，恢复记恢复，重复重试不重复计数 |
| R08 返回 | 建立弹层历史所有权；应用内关闭返回父记录；直接深链接用替换回退 | 发现→详情→阅读→关闭后不会增加关闭历史；浏览器前进后退、换章、深链接保持合理背景 |
| R09 空状态 | 统一清除所有筛选；空书架搜索入口真正导航并聚焦可见输入框 | 各筛选组合“查看全部”恢复总数；三类背景页均可进入搜索 |
| R10 可逆收藏 | 收藏可开关且不删除进度；移除书架保留短时撤销 | 取消收藏仍可继续阅读；再次收藏保留逐章状态；移除可撤销 |
| R11 大列表 | 书架与详情目录渐进分页/窗口；隐藏阅读目录延迟创建并有界呈现；操作保留焦点与位置 | 千本与两千章初始节点有界，查询覆盖全数据；分页键盘可达；单本状态尽量局部更新 |
| R12 诊断 | 检查入口始终写汇总；浏览器阶段命名，失败捕获截图、DOM、控制台、请求失败、trace | 注入失败后退出码非零且证据完整，成功组结果保留；普通完整检查通过 |

## 推进顺序

1. **准备**：保存审计与计划，确认工作区基线；启动三名 Agent，确定共享接口。R12 的最低失败记录能力优先由协调者实现。
2. **核心正确性**：A/B/C 完成 R01–R05 及必要调用接线；协调者修复 R02 服务端并设计 R06/R07。阶段产物是可重复恢复与数据一致性测试。
3. **交互与规模**：并行完成 R08–R11，保留默认阅读和品牌；形成具体交互截图与大列表节点/耗时证据。
4. **整合**：审查跨包接口、兼容性、错误语义与取消行为；运行 Python、JavaScript、语法检查和浏览器场景。补充测试仅针对本次风险和发现的新失败。
5. **交付**：更新版本、README、修复映射、复验和迁移说明；刷新本地服务，确认可访问。Goal 只有全部必要工作与验证完成后才标为完成。

## 验证方法

- 用合成可解码图片、坏图、空清单、慢后台和变化目录固定复现，避免把外部源短暂故障当成本地回归。
- 浏览器独立会话、临时端口与隔离数据；不清空用户浏览器、不批量下载真实漫画。
- 保留已通过的下载迁移、配额回滚、版本/票据、两个标签下载协调、240 页回翻、手机搜索和存储更新行为。
- 新增恢复、跨标签明确操作、路由/空状态/收藏、大列表与失败诊断场景；包括首次失败的可观测性，不用重跑成功掩盖初次失败。
- 性能测量记录设备环境、样本规模和同步/呈现口径；不把节点数或单次耗时等同于真实内存或所有用户 p95。

## 数据与运行约束

尽量保持数据库版本与原键名兼容。确需推荐反馈格式扩展时读取旧格式并保留已有偏好；新代码持有增量字段，清空语义可验证。下载图片不随在线目录删章而删除。对局部新模块使用静态路由白名单，不扩开放任意文件访问。

现有本地服务将在集成通过后重启到当前代码。保留 Git 基线，变更后数据不能靠简单回退源码承诺恢复；任何格式变更均写入交付记录。无需发布、上传或访问用户账户。

## 长期方向的后续规格

- 推荐评估：先收集候选字段完整率、可读打开率、持续阅读和明确收藏；固定基准查询/候选样本与实验口径后再调整排序。
- 源回归：按公开可访问样本记录逐源搜索、目录、清单、首图及检查时间；注册数量与当前可读性分别展示。
- 下一章预取：可关闭，限定清单/少量首图、并发及流量预算，不能抢当前阅读资源。
- 迁移/跨设备：明确书架、设置、偏好与图片的导出范围；完整离线壳、账号同步分别设计，避免误导现有本地缓存能力。
