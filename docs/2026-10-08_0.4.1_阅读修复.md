# Sardina 0.4.1 阅读修复

## 修复内容

**章节打不开时出现英文解析错误。** 嬉皮源间歇返回 403，同一时段本站实测收到纯文本 502。前端直接执行 `response.json()`，WebKit 显示 `The string did not match the expected pattern`，掩盖了实际请求失败。

- JSON 接口统一处理非 JSON 错误响应，显示中文原因和可操作的重试提示。
- 前台章节请求遇到临时 502 / 503 / 504 时，等待 650ms 后重试一次；两次请求共用原有的 45 秒超时和取消信号。
- 下载、预读、配额不足及普通 4xx 错误不自动追加请求；切章或退出会取消等待中的重试。
- 源站仍可能拒绝访问。重试失败时保留“重试本章”和“返回目录”，不会宣称内容已恢复。

**手机连续阅读出现方形断层。** 《装备我最强》147 章的第 75 个图片地址实际返回完全透明的 1×1 PNG，被阅读器按屏幕宽度放大为正方形；前后图片内容本来连续。

- 解码后只识别完全透明的 1×1 占位图，正常图片及不透明的 1×1 图片保留。
- 连续模式将占位图高度折叠为零，逐页模式按翻页方向跳过；章首、章尾及连续占位图均可处理。
- 图片清单不删项，保留源页码、已下载图片键和旧进度。旧进度落在占位图时移到相邻内容页。
- 空占位图不充当章末内容，已读判定使用最后一张实际内容图。

## 验证范围

运行 `uv run python scripts/check.py --browser`。此次只补充两组 API 测试和一个浏览器场景，复用原有检查流程。

发布候选完整检查通过：440 项 Python、232 项 JavaScript、前端语法及 8 组浏览器场景。Chromium 真实断网后通过深链接、刷新、新标签和下载入口重开，140px 阅读位置完整恢复，无页面脚本错误。

新增场景覆盖临时错误恢复、持续错误提示、手动重试、连续画面接缝、双向翻页、透明与不透明小图区分、旧下载及旧页码恢复。Chromium 和桌面 WebKit 均验证报错与显示逻辑；移动视口不等于 iPhone 真机。

当前机器已安装的 WebKit 测试运行时在不加载产品代码的空白页上也无法写入 IndexedDB Blob，因此不把它计为离线下载验收通过。离线缓存、下载重开和断网位置恢复另用 Chromium 检查。此版本未更改下载存储格式。

本地验收证据位于 `output/playwright/release-041-20261008/`，不随源码发布。版本号同步到 Python 项目、Node 项目、锁文件及 HTTP 服务标识；Web 离线资源清单包含新增的 `api.js`。
