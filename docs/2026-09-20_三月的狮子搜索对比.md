# 「三月的狮子」搜索对比

本轮按用户请求进行观察与分析，未修改应用实现。

## 证据

- 直接读取用户当前内置浏览器本地搜索页：`http://127.0.0.1:8765/s/三月的狮子`，页面显示 182 条结果、11/11 源完成。
- 原版同关键词接口响应：`output/playwright/march-original-search.json`，本次原始数据 174 条。
- 原版实际浏览器页面：`https://mangayun.com/s/三月的狮子`，显示「收录 4 部」。初始内置浏览器读取原站超时，改用已有 Playwright 验证浏览器重新打开同一关键词确认；未声称读取到了用户 Chrome 的原版标签页。
- 原版截图：`output/playwright/march-original-desktop.png`。
- 原版结果页前端证据：`work/20260920-mangayun/evidence/bundles/ResultList-BqQeXmEx.js`。

## 可复核的差异

| 项目 | 当前本地版 | 原版实际呈现 |
|---|---|---|
| 结果规模 | 182 条原始记录 | 174 条原始记录，筛选聚合成 4 张作品卡片 |
| 全部页排序 | 按源顺序拼接，包子 80 条占满前段 | 标题相关性及源优先级排序，准确命中在前 |
| 同名跨源 | 不同源分别占一个封面格子 | 同名作品在卡片内切换源 |
| 第一组准确命中 | 漫画之家《三月的狮子》排在第 81 条 | 第一张卡片，可切漫画之家/图库/如漫画，目录 214 话 |
| 繁体标题组 | 混在包子、拷贝、巴士的各自结果里 | 第二组《三月的獅子》，包子/拷贝/巴士，包子目录 215 话 |
| 数字标题组 | 漫画柜《3月的狮子》埋在后面，封面缺失 | 独立卡片，作者/简介/分类，目录 192 话 |
| 章节入口 | 必须先打开详情弹窗 | 卡片下直接点章节，有正序/倒序/更多 |
| 元数据 | 一行作者或更新时间，很多显示「点击查看章节」 | 可见卡片主动加载详情，补作者、状态、简介、分类与目录 |
| 信息结构 | 多列小封面网格，书架式浏览 | 大作品卡片，封面+资料+源切换+章节，面向精确找书 |

第四张原版卡片是《三月的兔子们》，说明原版也保留部分相近结果，并不是完全精准检索。

## 实现根因

1. `web/app.js:67` 对结果直接 `flatMap`，没有标题相关性、全局排序、跨源作品聚合。
2. `web/app.js:43` 的 `card()` 被书架与搜索共用；当前模板只足以做简单封面列表，不具备原版搜索卡片的层次和动作。
3. 原版前端会做标题规范化、相关性打分、低分过滤、同人等词的降权、同名源合并；还按可见区域加载详情，并限制详情并发为 2。本地没有这一层。
4. 本地原生 DM5 家族搜索只提取 `title/url/href`，没有封面，导致动漫屋/漫画巴士/漫本大批纯文字占位。
5. 漫画柜封面来自 `cf.mhgui.com`；`server.py` 的 IMAGE_DOMAINS 有 `manhuagui.com`，没有 `mhgui.com`，本地代理会拒绝。这是确定的本地配置遗漏，不能归因于源站不稳定。
6. 本地漫本 12 条、Komiic 3 条与原版漫本 0 条、Komiic 1 条存在额外差异；尚不能仅凭这次计数认定具体服务端原因，需要进一步核对原生解析范围和搜索策略。

## 原版也存在的不足

原版的简繁映射表未覆盖「獅→狮」，也没有把本例的「三月」与「3月」归一。因此仍将同一作品分成 3 张卡片，部分繁体数字标题结果还被相关性阈值过滤掉。对齐时应实现受控的别名规范化，结合作者/版本信息保留版本边界，而不是机械复制这项缺陷。

## 修复优先级与验收

1. P0：标题规范化、精确匹配优先、弱相关过滤；同名跨源聚合。分别标明原始候选数与作品组数。
2. P0：改成原版同类作品卡片，卡片内切源并直达章节；可见区域才补充详情，限制并发。
3. P1：补齐原生搜索封面/作者等字段；修正漫画柜 CDN 白名单，提供受控的失败回退。
4. P1：保留「相关结果」入口，与准确命中分开；避免将读者需要的原始结果永久丢弃。
5. 使用本例作为固定回归：繁简体和数字别名覆盖，准确命中在首屏，同一本书源可切换，首屏无大量无关作品，不将“接口 200/测试通过”当作搜索质量验收。

上一轮的 20 项测试验证了接口、分页、缓存和基础流程，没有覆盖搜索相关性、聚合和与原版的结果页体验对照。上一轮对齐完成程度的表述需要以此修正。
