# Sardina 体验修复执行计划

基线为 `f3532aa`。依据本轮代码审查、手机尺寸浏览器复现和线上推荐数据抽查，按 Intent → Spec → Impl → Verify 执行。修复前证据保存在 `output/audit-20261008/`。

目标是让同一本漫画的搜索、收藏、换源、阅读和推荐保持连贯，减少等待并保留用户的阅读位置。保持现有手绘界面和轻量架构；采用局部修改，复用现有验证，不扩充重复的单元测试。

## 工作范围和验收

| 编号 | 问题与意图 | 实施规格 | 验收条件 | 负责 |
|---|---|---|---|---|
| F01 | 逐页放大后续读跳回顶部 | 逐页模式从实际滚动位置计算图片内偏移，保存、恢复和尺寸变化使用同一坐标规则 | 图片滚动后刷新、离开重进仍恢复相同内容；连续模式保持正确 | 阅读 Agent |
| F02 | 跨源重复书架、续读断开和反馈失效 | 共用名称归一化；书架按可信作品关系折叠并保留来源记录、收藏和进度；换源提供章名或编号匹配，匹配不明确时让用户选择；推荐过滤使用同一关系，明确冲突作者或版本保持区分 | 同一作品两源显示一个书架入口，可查看来源；换源能定位相应章节；不同作品不会被强行合并；不感兴趣覆盖已识别的关联来源 | 数据 Agent，页面 Agent 接线 |
| F03 | 书架简繁及别名搜索不一致 | 复用搜索名称归一化，对书名、别名和作者执行一致的查询匹配 | 保存繁体书名后简体可查，常见别名可查，作者搜索保留 | 数据 Agent |
| F04 | 打开漫画等待首页背景 | 源列表初始化与背景加载解耦，当前路由准备好即恢复；背景失败单独处理 | 挂起首页数据时详情和阅读仍开始加载，不出现后到响应覆盖当前页面 | 页面 Agent |
| F05 | 后台请求抢占阅读清单 | 元数据请求区分前台详情/章节与后台搜索、推荐和预取；复用已有有界调度思想，预留前台容量，保持总上限 | 慢后台占满其额度时前台章节仍能开始；完成或失败均释放容量 | 协调者 |
| F06 | 返回时残留下载弹窗 | 书架、下载和源管理纳入统一弹层历史；关闭、Escape、浏览器返回按层退回，深链接仍能安全回退 | 首页→发现→书架→下载后返回只关下载，再返回关书架，背景地址不提前改变；前进和直接链接可用 | 页面 Agent |
| F07 | 排行榜来源和页码丢失 | URL 保留来源、周期与页码；切换筛选和翻页同步，刷新和前进后退恢复；无效参数回到有效选项 | 来源 B 周榜第 2 页刷新、复制链接和返回后保持选项，分页不产生循环请求 | 页面 Agent |
| F08 | 推荐元数据不足和失败不重试 | 显式刷新清除失败尝试；成功缓存继续复用；补资料时重新归并可识别作品；优先补足可见候选的缺失作者、简介和分类；有实际内容才用于排序 | 首次资料超时后刷新能恢复；不会重复请求已有资料；补全后排除已收藏/忽略的关联作品；推荐说明可解释 | 数据 Agent，协调者补源字段 |
| F09 | 下载后无法稳定离线重新打开 | 缓存应用静态资源与最近成功的源列表，离线导航回退到应用壳；图片仍由现有 IndexedDB 管理；保留下载目录离线入口；更新采用版本化缓存 | 在线访问并下载后断网刷新、重新打开本书仍可阅读已下载章节；未下载内容明确提示联网；恢复在线后能更新应用 | 协调者，页面 Agent 接线 |
| F10 | 备份不包含阅读设置和推荐偏好 | 在兼容旧书架 JSON 的基础上增加可选偏好部分，包括全局/单书阅读设置、源偏好、推荐偏好；明确图片不在 JSON 中 | 老备份仍可导入；新备份可在干净浏览器恢复书架与设置；导入不清除现有下载 | 页面 Agent，数据 Agent 提供反馈接口 |
| F11 | 读完后仍需手动标记 | 用户到达最后一页末尾后标记当前章已读，保留显式撤销；不把预加载完成当作读完 | 预读不触发已读；读到末尾触发；手动撤销不被同会话立即覆盖；目录与书架同步 | 阅读 Agent |
| F12 | 换章等待与手机翻页步骤多 | 章末按当前省流设置预取下一章清单及少量首图，使用后台额度并可取消；逐页且未放大时横向滑动翻页，单击保持工具栏切换，遵循左右阅读方向 | 下一章复用已预取数据；当前页优先；省流关闭额外预取；滑动不误触工具栏，缩放和连续滚动保持原行为 | 阅读 Agent，协调者请求调度接线 |

## 并行分工

三个 Agent 共享工作区，按文件划分所有权，接口先约定再接线。

| 工作包 | 独占修改范围 | 对外接口 |
|---|---|---|
| 阅读 Agent | reader.js、reader-model.js、reader-gestures.js、reader.css、image-loader.js，必要的现有阅读检查 | 使用现有 onChapterRead；预取请求带 purpose；向协调者报告新增静态模块 |
| 数据 Agent | book-identity.js、library-model.js、recommendations-model.js、recommendations-feedback.js、recommendations-ranking.js、recommendations-metadata.js、recommendations.js，新增作品关系模块 | 输出书架分组与关联进度匹配函数；向页面 Agent 提供导出/导入反馈接口 |
| 页面 Agent | app.js、route-history.js、discovery-model.js、discovery.js、downloads.js、index.html、app.css 及专用界面 CSS | 集成数据函数；离线资源注册由协调者添加独立脚本；source-purpose 按约定传递 |
| 协调者 | server.py、client 后端、离线 worker 与注册模块、静态清单、浏览器验收、文档、发布 | 统一前后台请求参数、静态缓存更新和整体交付 |

所有权外修改需先通知对应负责人，避免覆盖进行中的工作。Agent 不提交、不推送、不部署，集成后由协调者统一处理。

## 执行顺序

1. 固定基线、创建 Goal、保存本计划与验收矩阵。
2. 三条 Agent 工作线并行推进 F01–F04、F06–F08、F10–F12；协调者实施 F05 与 F09，并检查真实源的推荐字段。
3. 完成接口接线：作品分组与页面、弹层与路由、阅读预取与请求优先级、离线壳与本地下载入口。
4. 运行各模块现有检查，再运行一次完整现有检查；围绕上述问题组织少量组合浏览器流程。只针对新失败追加检查，避免重复测试实现细节。
5. 检查 320/393px 手机、桌面、键盘操作和离线恢复；审查最终 diff、旧数据兼容性及新增缓存清理方式。
6. 更新计划和交付说明，按当前项目既有授权与发布流程同步 GitHub、线上服务和本地服务，保留上一发布目录用于回滚，验证公网资源与关键接口。
7. 全部必要修复、集成验证和交付完成后结束 Goal；明确说明仍依赖外部漫画源的实时可用性。

## 验证与完成标准

优先复用已有单元检查与浏览器场景。新增行为集中在阅读续读/手势、跨源书架/反馈、弹层/榜单路由、离线重开四条组合流程中验收，浏览器使用独立数据，不清空用户记录，不批量下载真实漫画。

受控慢请求验证前台优先；可解码的小图片验证阅读和离线；真实推荐响应验证字段质量。记录首次失败及修复原因，不用重复运行掩盖问题。实际源可用性与本地逻辑通过分别报告。

保留原源条目和源内进度，避免以模糊标题覆盖已有记录。导入为合并，不删除下载；离线缓存只保存应用资源和必要目录信息，不把所有 API 回应长期缓存。
