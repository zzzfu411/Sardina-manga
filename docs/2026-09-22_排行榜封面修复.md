# 排行榜封面修复

## 原因与目标

用户反馈排行榜没有漫画封面。默认漫画柜的日／周／月／总榜是文字表格，源站 HTML 不含作品图片；原解析器据实返回空 `coverUrl`，前端又将这种榜单整体切成文字行，缺少从作品页补图的步骤。漫本人气榜本身带封面，不受这个缺口影响。

目标：所有排行榜使用封面网格，保留源站的完整条目、名次、顺序与详情入口；只补取可见范围附近的缺失封面，失败能单独重试，快速切换榜单时不串图。

## 实现

1. 增加 `POST /api/discovery/cover`，接收 `siteId`、`detailUrl` 和可选布尔 `refresh`。仅接受漫画柜／漫本规范作品地址，读取一份受大小、时间、重定向限制的 HTML。
2. 在主作品区域解析真实封面，核对作品地址、标题和图片归属。不猜 CDN 路径，不从推荐栏拿其他书的封面，不调用完整详情接口或解析章节。
3. 服务端使用独立 6 小时、最多 512 项的封面地址缓存；同时最多读取 4 份作品页，等待执行位置超过 5 秒时报可重试错误。现有搜索与榜单缓存独立保留。
4. 前端以视口上下 160px 为预加载范围，最多同时补 3 本；使用独立的有界地址缓存。切换榜单取消旧队列，离开发现页暂停，迟到响应无法更新新榜单。
5. 封面加载与榜单渲染分开进行，补图不改变条目和名次。单张失败显示“封面暂不可用”和“重试封面”，重试刷新该书的封面地址并换用图片请求缓存标记。
6. 保留原有桌面六列、平板四列、手机两列布局，以及标题／封面点击打开详情的行为。

## 边界

封面依赖源站的作品页及图片服务，源站连接失败时仍可能需要重试。本次仅给已接入的两源发现列表补图，不把搜索源数量等同于排行榜源数量。缓存保存地址与元数据，不新增图片落盘或批量离线下载。
