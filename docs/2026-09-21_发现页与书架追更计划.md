# 排行榜、最近更新与书架追更：Intent → Spec → Impl

## 目标与审计

用户需要从云漫直接发现热门作品、浏览源站最近更新，并检查已收藏漫画是否有新章节。当前首页 `/api/home-sections` 仅读取静态精选；已接入 25 源的搜索/目录/阅读链路可复用，但没有发现列表或书架目录变更模型。APK 提取规则中有排行榜和更新入口，旧域名与规则本身不能证明当前可用。

先验证漫画柜、漫本及 6漫画等已接入源的公开列表，优先启用至少两个能够返回真实列表、且抽样作品能通过现有详情接口打开目录的来源。不为凑数引入未验证来源，不改变搜索源覆盖。原网页数据属于相应来源的排名，不合成为“全网排行榜”。

## 产品规格

### 首页发现

- 保留原有搜索、封面墙与继续阅读，搜索区之后新增一个左对齐的“发现漫画”区域。
- 两个入口：“热门榜”和“最近更新”；来源选择器只列出已验证且支持当前类型的源。日/周/月/总榜仅在源站提供并验证后显示。
- 保留源站顺序、明确榜单周期和名次；更新列表显示源站实际提供的更新时间文字，不用抓取时间冒充作品更新时间。
- 显示来源链接、数据获取时间；可刷新与分页。切换来源/类型会取消旧请求，旧结果不能覆盖新选择；加载、空结果、失败和重试均有明确状态。
- 条目使用现有详情与阅读流程；不为每个榜单作品预取目录、章节或阅读图片。

### 书架检查更新

- 手动按钮触发，最多 2 本同时检查，显示成功/失败进度，支持停止。不会在后台自动扫描所有收藏，也不会安排定时任务。
- 优先检查在读与想读作品；已读作品也允许用户主动检查，具体界面保持一个检查入口。源失败彼此隔离，保留旧有效结果。
- 第一次成功取得完整非空目录时建立基线，仅显示“首次记录”，不把已有章节当成新更。
- 后续以去重章节 URL 的稳定指纹和章节数对比：新增数量增加可显示“有新章节”；同数量替换或减少显示“目录有变化”；仅改名或调换顺序不应误报新增。
- 只保存紧凑指纹、目录数量、检查/变更时间，不复制完整目录进 localStorage。变化提示可以在用户打开详情查看目录后消除；它表示“待查看的目录变化”，不等于未读章数。
- 目录检查不改变章节、页码、页内位置、实际阅读时间或在读/想读/已读分类。书架删除、导入和检查并发时按书籍唯一键合并；不把已删除的书重新加回。
- 备份兼容 v1；如保留追更元数据，字段必须可选并验证。空目录、限制页面或请求错误均不能覆盖旧基线。

## 接口与模块分工

后端独立 `client/discovery.py`：

- `sources()` 返回 `[{siteId,siteName,modes:[{kind,label,periods:[{id,label}]}]}]`，kind 为 `popular` 或 `latest`；无周期时 periods 为空。
- `normalize_request(body)` 返回规范化 `(siteId, kind, period, page)`；限制源、类型、周期、页码，不能传任意 URL。由服务端构造固定允许的外部地址。
- `fetch(siteId, kind, period, page)` 返回 `{siteId,siteName,kind,period,page,items,hasMore,sourceUrl,fetchedAt,label}`。items 使用现有 book 字段，另可有 `rank`、`updatedAtText`、`latestChapter`，不虚构缺失值。
- `GET /api/discovery/sources` 和 `POST /api/discovery`；native 模式启用。列表默认缓存 5 分钟，显式刷新可更新所选列表，缓存仍有界；失败不以空成功覆盖。
- `/api/details` 增加可选布尔 refresh，用于用户明确的书架更新检查；普通详情继续缓存。

前端独立 `web/discovery.js/css`：`createDiscovery({root,api,imageUrl,onOpenBook})`，提供 `show()`、`hide()`；主应用负责挂载、首页切换与静态路由。

追更独立 `web/library-updates.js`：紧凑目录快照、对比、合并和可取消的有限并发控制；主应用负责书架按钮、提示和持久化接线。阅读器不增加新的网络或保存逻辑。

团队分工：data Agent 验证/实现发现源及测试；search Agent 实现发现界面与相关模型测试；reader Agent 实现追更模型和取消/并发测试；主 Agent 负责接口、书架 UI、主应用集成、兼容性、实际联调和文档。

## 界面与实现顺序

沿用现有颜色：背景 `#f5f9ff`，内容 `#ffffff`，主色 `#2677ed`，正文 `#243b58`，说明 `#71829a`，边线 `#dce8f6`。字体沿用系统中文无衬线；封面和书名主导发现区，名次只用于真实排行。桌面网格、手机双列；筛选控件可换行，320px 无横向溢出。所有操作支持键盘，默认不新增动画。

1. 写清规格并验证候选列表，保存真实响应与来源证据。
2. 三个独立模块并行开发，后端和主应用按上述契约接线。
3. 运行解析/缓存/URL/旧备份与追更语义测试。
4. 真实 HTTP 验证每个启用来源的列表与普通漫画目录；排行榜不额外消耗阅读图片配额。
5. 独立浏览器验证发现→详情、类型/周期/分页、快速切换、失败重试、手机布局，以及追更首次/新增/重排/失败/停止/删除并发。
6. 更新 README 与本计划的验收结果；重启本地服务并检查实际提供最新资源。

## 验收要求

数据真实性优先：只展示源站实际支持的维度；列表时刻与作品更新时间分开。分页不得重复第一页或把未知结束当作已结束；不稳定或不可确认的周期不提供。追更的首次基线和新增状态必须区分；并发检查不能覆盖阅读状态、复活删除项或在停止后写入晚到结果。已有 25 源搜索、阅读位置与书架备份回归必须继续通过。

以上数量是 2026-09-21 的现场样本，不写死为榜单总数。漫画柜更新保留源站日期文字，漫本首屏未提供条目日期时留空；获取时间单独显示。漫画柜无封面的榜单使用桌面双列、手机单列的紧凑条目，有封面的列表使用响应式网格。

书架已提供检查、停止、只看有更新与失败重试；首次基线不提示新增。指纹采用去重、排序后的完整章节 URL 集合，忽略改名与排序；数量增加为“有新章节”，替换或减少为“目录有变化”。查看相应目录后清除提示，有更新提示的书籍先打开目录，普通继续阅读保持原行为。读取旧缓存不能倒退新基线；新目录检查不能覆盖已有阅读页码、阅读时间或分类，停止后的响应不能写入，检查中删除的书不会复活。

所有目录检查只返回元数据，最多两路并发。书架只存指纹、数量和时间，不保存第二份完整目录。v1 备份可携带经验证的可选检查状态，独立合并较新记录；旧格式继续可用。搜索源保持 **25 个**，本轮未增加 COLAMANGA、未改变 Komiic 图片配额流程。

### 保留的限制

- 发现列表目前仅启用上述两源，不能把 25 个搜索源表述为 25 个榜单源；它们是各站榜单，没有合成全网排名。
- 漫本分页末尾按官网空数组协议处理，固定测试覆盖结束分支；未遍历全站以确定当时最后一页。下一批失败或出现重复数据会明确报错，不假装已结束。
- 列表通常缓存五分钟，可手动刷新；源站变动、验证页或结构变化会显示失败。更新目录依据源返回的有效章节集合判断，提示不是精确的未读章数。
- 追更为手动检查，本轮没有后台定时扫描、跨设备同步、离线下载或下一章图片预取。`mangayun` 兼容模式不混入原生发现链接。
