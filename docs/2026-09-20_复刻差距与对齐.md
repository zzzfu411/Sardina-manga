# 云漫复刻：差距与本轮对齐

对照日期：2026-09-20。目标来自 [LINUX DO 项目帖](https://linux.do/t/topic/2919011)、[云漫网站](https://mangayun.com/)、项目中已有前端/API 证据，以及本轮浏览器截图。此报告区分原帖承诺、仓库原状、代码接入和实际验证，不将接口脚本当作已交付产品。

## 核心结论

原仓库是接口研究项目：四个 Python 客户端、解码脚本、接口文档和前端取证，没有可启动的 Web 产品。差距主要是缺少完整使用流程，而非少几个接口。

本轮补为一个**可在本机使用的漫画搜索与阅读应用**。默认直接连接原生源，保留云漫聚合接口兼容模式。它已经具备首页、搜索、详情、阅读器和本地书架，但尚不能称为原站全部能力的完整复刻。

## 逐项对照

| 原帖或原站能力 | 改动前 | 本轮结果 | 仍有差距 |
|---|---|---|---|
| 可访问的桌面/手机网站 | 无 | `server.py` + `web/`，无前端构建步骤 | 仅本机服务，无公开部署 |
| 蓝白首页、中央搜索、可点击封面背景 | 无 | 自行实现同结构页面和原创 SVG 云朵书本标识 | 非像素级复刻；没有原站风铃挂件与原版商标素材 |
| 多源聚合检索 | 单次 CLI JSON | 11 源统一适配，前端最多 4 路请求，逐源结果、筛选、失败状态、停止/重试 | 未接入歪歪可阅读链路；源站自身稳定性不受本项目控制 |
| 选择漫画、完整章节目录 | 各脚本格式不一致 | 统一详情和章节接口、过滤和排序、开始/继续阅读 | 大部分原生源的简介、作者等元数据较原站简略 |
| 多源切换 | 需手改 CLI 参数 | 结果源筛选、详情“换源查找” | 不自动把不同源的版本/章节映射为同一话，避免错跳 |
| 竖屏沉浸式阅读 | 只有图片 URL | 真实图片显示、懒加载、单页重试、章节跳转、前后章、明暗/宽度/沉浸 | 未实现下一章预取和 Comicbox 解密重排 |
| 书架、阅读历史、续读 | 无 | 自动入架、章节与页码保存、移除、排序、刷新恢复 | 当前是同一浏览器内的存储 |
| LINUX DO OAuth2 与跨设备自动同步 | 仅研究了原站登录入口 | 界面明确标注未同步；提供备份导入导出 | 需要独立 OAuth 应用、回调域名、会话与用户数据库；未复用原站 client_id 或登录态 |
| 首页书目 | 无应用层入口 | 本地精选元数据，点击后实时加载目录 | 不是实时热度榜/更新时间榜；未实现运营后台 |
| 分享和刷新路由 | 无 | `/s/`、`/m/`、`/read/` 均可直接访问，书籍链接携带最小标题信息 | 旧式无标题链接在无本地书架时，部分原生源可能显示“漫画” |
| 图片代理 | 只有原站 URL 帮助函数 | 本机代理：域名白名单、重定向复核、图片类型和 12 MiB 限制 | 新 CDN 需要显式维护白名单 |
| 测试 | 无 | 离线回归及真实浏览器检查 | 不将抽样成功等同于全源、全书籍可用 |

## 原先文档中的“12 源已打通”需要如何理解

旧报告是某时点的接口样本验证，并非产品验收。具体差距及本轮修复：

1. 嬉皮的 `hipmh_chapters()` 默认只取一页。本轮按总数继续翻页，检测重复/缺页；将目录 hid 转换为 v2 阅读接口需要的 token。
2. 拷贝的 `copy_chapters()` 只请求 default 分组、offset=0。本轮遍历全部分组和分页。
3. 拷贝搜索 `limit` 不能超过 30。本轮实测 `limit=50` 返回 HTTP 200 但业务 `code=210`；修正为 30，并对 JSON 业务错误和 GraphQL errors 抛出真实错误，避免伪装为无结果。
4. DM5 家族原先仅有 `first_chapter_url()`。应用层新增目录提取与去重；源站页面格式变化仍可能需要维护。
5. 嬉皮封面与正文使用不同 CDN。封面修正为证据中的 `cover.s3imgs.top`，正文保留签名图片 CDN；修复后的封面经本机代理实测 200 / image/webp。
6. Comicbox 脚本返回逻辑 jpg，原始对象还需要分片 AES 解密和图像条带重排。计算切片数不代表已能显示图片。本轮明确禁用它的阅读入口，保留既有研究脚本。
7. 原站书架的 OAuth 应用及用户数据库属于原站。知道登录入口不等于本项目已具备可独立运行的同步系统。

## 数据层与运行边界

```text
浏览器
  ├─ 首页 / 搜索 / 详情 / 阅读器
  ├─ localStorage：搜索历史、书架、章节/页码、阅读偏好
  └─ 本机 HTTP 服务
       ├─ native（默认）：providers → 现有源站解析器
       ├─ mangayun（可选）：已有 MangaYun 客户端 → 原站 API
       ├─ 短时有界 API 缓存，同一 key 合并并发请求
       └─ 限定域名的图片代理 → 源站 CDN
```

默认模式不会调用 mangayun.com 的搜索/详情/章节服务。精选书目来自公开首页元数据，已剔除旧的 views 与更新时间，避免显示成实时数据。前端是新写的原生 JavaScript，没有把取证得到的整套 Vue bundle 直接部署为本站。

LINUX DO 登录、云同步、部署域名和凭据没有伪造占位成功状态。导入导出是手动迁移工具，不是云同步。

## 后续优先级

1. **跨设备身份与存储**：独立 LINUX DO OAuth 应用、服务端会话、按用户隔离的书架数据库、冲突合并、注销和本地书架迁移。
2. **全源可靠性**：每个源保留可重放 HTML/JSON 夹具，补齐复杂目录/元数据，按真实故障做解析器回归；落实请求总时限和源级并发预算。
3. **Comicbox 图片链路**：分片下载、解密、条带还原、正确性样本及资源上限，验证后再展示为可读源。
4. **运营与上线**：可维护的首页配置、运营身份、部署方案、日志与监测；再考虑热门榜和下一章预取。

这些是明确剩余工作，不包含在本轮“已完成”中。
