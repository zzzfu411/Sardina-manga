# 云漫产品审计（实现前基线）

日期：2026-09-20。目标：让读者快速找到正确作品、选择可用源、稳定读完并继续阅读。

## 方法与证据边界

本次先对照用户本地浏览器与原版的同关键词结果，再检查数据适配、页面状态、路由、持久化和阅读器实现。具体原版证据见 [搜索对比](2026-09-20_三月的狮子搜索对比.md)，包括原始响应、截图及结果页前端文件。原版 174 条和本地 182 条是本次观察值，不是永久验收常量；源站会变化。

基线验证：`python -m unittest discover -s tests -q` 的 20 项测试通过，`node --check web/app.js` 通过。这些测试覆盖接口、分页、缓存与校验，不能证明搜索质量和阅读体验。

下文分别标注「已观察」「代码确认」和「待运行验证的风险」，避免把推断当成复现。

## Intent：用户要完成的事

1. 输入熟悉的作品名，首屏看到准确作品，而不是逐个扫描不同源的泛匹配结果。
2. 在作品内比较可用源及其目录，点选章节即可开始阅读。
3. 阅读时保持图片位置稳定，能跳页、找章节、重试坏页、切换明暗和进入沉浸；手机上的按钮可触达。
4. 离开或刷新后回到读到的位置，切章和快速操作不会污染其他作品的进度。
5. 源站失败时知道哪个源失败，并有重试或换源路径。

## 对齐与取舍

原版优势是作品级信息组织与可操作的搜索卡片。本轮沿用其蓝白视觉和橙色标题、宽卡片及章节网格，保留本地项目品牌与结构。原版仍把本例分成三个标题组；本轮改进受控别名，不照搬这个缺点。

跨站同名不必然是同作品：有明确版本标记或作者冲突时分开；没有证据时保守处理，不凭封面相似猜合并。不根据缺失状态制造「连载中/已完结」。

本轮交付搜索与阅读闭环以及必要的数据修复。LINUX DO OAuth/云同步需要服务端凭据与部署；Comicbox 需要独立解密管线，继续如实标记未接入。这两项不冒充已完成，也不阻塞本轮已授权的本地迭代。

## 验收结论的规则

固定样本验证算法；实时源验证兼容性；真实桌面和手机浏览器验证交互。记录每项结果和失败源，不以接口 HTTP 200、单一截图或原始结果数量替代用户任务验收。实施与验收计划见 [Intent → Spec → Impl](2026-09-20_Intent-Spec-实施计划.md)。
