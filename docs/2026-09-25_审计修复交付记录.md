# Sardina 0.3.0 审计修复交付记录

本轮按照 [全面审查](2026-09-25_全面审查与优化建议.md) → [执行计划](2026-09-25_审计修复执行计划.md) → 实现与验收推进。重点修复阅读和下载的恢复能力、数据保留、资源消耗、手机搜索与推荐数据链路。保留 Sardina 手绘品牌、25 个源入口及既有书架存储协议。

## 审计项与实现

| 审计项 | 实现及验收结果 |
|---|---|
| F01 第三方脚本执行与 TLS 降级 | 移除 DM5 家族 `node -e` / `eval` 回退及两处不验证证书的重试。已知 packer 只按数据解析，限制输入、参数与展开长度；未知格式报错。已验证恶意表达式不进入进程执行、正常格式可读、超限被拒绝、证书失败不发第二次请求。嬉皮固定可信解码代码保留。 |
| F02 部分下载锁在过期地址 | 本地页优先显示；缺页请求失败后合并刷新一次章节清单并重试，手动重试可再次取新地址。切章后迟到响应失效。真实浏览器用例中旧地址失败后刷新 1 次，第 2 页恢复，第 1 页未重下。 |
| F03 刷新清单丢失已存页 | 只有经过核验的 MangaBZ 图片 `key` 票据更新允许按稳定身份复用；路径、`cid`、顺序、数量及其他参数变化不擅自视作同图。未知内容变更保存独立版本，完成新章后才删除旧页；空间不足事务回滚，旧页仍可读。 |
| F04 本地目录遮住新章节 | 本地下载即时打开，在线时独立刷新作品目录；详情与阅读器均提供“更新目录”。测试确认新增第 2 话可达，当前本地图片不重下；离线完整章不请求目录或远端图片。 |
| F05 可可迁移与源状态 | 可可漫画网络请求改走已验证的 `keke2026.com`，旧 `www.cocoecar.com` 作品和章节身份保留。重定向仅允许已知域名及相同作品/章节。源目录显示最近实际请求的能力、结果、时间与耗时；搜索无匹配、受限和失败分别记录，服务端原子持久化。 |
| F06 手机搜索路径过长 | 全部源筛选与作品内其他来源默认折叠，仍可展开访问全部 25 源；当前选择保留。文案改为“已响应”与具体失败数。393×852 场景首个章节入口 y=579；320/393 像素布局无横向溢出。 |
| F07 已读图像持续驻留 | 当前显示范围附近保留图片，远处释放图片源与消费者，保留页面尺寸及位置。逐页遍历 240 页后仅 4 张图片仍有 `src`，回翻第 1 页正常，240 个尺寸占位仍在。此数值不是浏览器真实内存测量。 |
| F08 缓存和全局请求预算 | 有效缓存只持短锁，冷请求按实际 key 合并；失败后可重试。元数据、图片分别设置服务端 8 路并发，图片缓存最多 96 项/32 MiB。测试覆盖无关慢请求不阻塞命中、同 key 失败合并、12 个并发图片请求的在途数不超过 8。 |
| F09 进度保存扫描全书架 | 新增记录级 `updateBook`，保存时只解析和写入目标记录，保留字段时钟、删除保护和跨标签合并；翻页不重建推荐画像。千本真实 localStorage 场景 7 次更新只写 7 条，无存储枚举；原有备份/合并测试通过。内存中的书架顺序仍需维护，未宣称算法整体 O(1)。 |
| F10 跨标签重复下载 | Web Locks 按章节协调，获得锁后重读任务；BroadcastChannel 通知状态。真实两个标签下载同一两页章节共 2 次图片加载。generation 与任务 token 防止迟到写入复活已删除下载。浏览器不支持 Web Locks 时明确提示，避免假装已协调。 |
| F11 下载目录重复及容量不透明 | IndexedDB v2 将作品目录、任务摘要、各版本图片分开；同书 100 个下载共享 1,000 项目录。列表只读摘要，显示刷新节流到 120 ms；删除末个任务回收无引用目录。界面区分图片预算、浏览器空间及持久存储许可。当前仍刷新摘要列表，并非所有 UI 行都做增量更新。 |
| F12 推荐缺少内容资料 | 作者、简介、明确题材、语言和版本字段保留，实际打开作品可补入本地资料缓存。7 个适配源提供不遍历章节的轻量资料接口，每轮最多补取 2 本，卡片先显示；缓存最多 200 本/7 天。近期章节/图片失败作为有限降权信号，不把未知作品标成已验证可读。 |
| F13 曝光压过相关性、缺质量信号 | 曝光改为有上限且随时间衰减的惩罚；明确收藏、有效阅读和读完采用不同权重。记录推荐打开后成功显示首个阅读页、累计到第 3 个不同阅读页、打开失败，按打开会话去重。相关性、曝光恢复、版本过滤、反馈清空和迟到资料响应均有回归。 |
| F14 缺持续验收和版本记录 | 建立本地 Git 修改前基线，纳入源码、固定浏览器场景、统一检查入口与迁移文档，排除 APK/输出/运行缓存。配置 GitHub Actions；本地相同入口已通过，尚未配置远端或执行托管 CI。 |

## 更新、数据与回退

1. 当前服务已更新为 Sardina 0.3，继续使用 `http://127.0.0.1:8765/`。刷新页面加载新前端；仍使用原浏览器、原域名和端口，才能访问原有本地数据。
2. 书架 localStorage 键及 JSON 备份协议保持兼容。下载数据库名字仍为 `sardina.downloads.v1`，数据库内部版本自动从 1 升至 2；升级事务搬迁图片 Blob、拆出共享目录和摘要。已有页面持有旧数据库时，关闭其他 Sardina 标签后重试，不需要清除站点数据。
3. 同页身份目前只额外确认了 MangaBZ 的 `key` 票据更新。其他源 URL 不确定的变化一律按内容版本处理。最多保留 3 份旧版本；达到上限时停止并提示恢复旧缓存或显式删除，不悄悄清空。新章完整保存后清理旧版本。
4. 下载图片预算为 1 GiB，计入保留的旧版本。浏览器的实际空间和清理策略单独显示；申请持久保存不代表浏览器必然授予。完整下载可断开外网阅读，本地服务仍须运行；尚未存下的页面需要网络。
5. 书架 JSON 不包含下载图片、推荐偏好和阅读设置。源码回退也不会回退浏览器数据库。**已升级 v2 的浏览器不要直接运行仅支持数据库 v1 的旧下载代码**；优先向前修复，旧代码复现使用独立浏览器资料，不要求用户删除下载。
6. 修改前源码快照及 SHA-256 在 `output/repair-20260925/before-source.tar.gz` / `before-sha256.json`；Git 基线提交为 `ca0415b`。仓库没有远端，本轮未发布或上传项目。

## 后续工作的边界

本轮修复了执行计划内的实际缺陷，以下更大的产品或验证工作仍保留为独立迭代：

- 注册数为 25；2026-09-25 原版清单快照的 11 个 ID 全部覆盖。并未重验所有源的所有漫画，也不能据此宣称全时可读。健康记录来自已经发生的请求，未进行常驻后台探测。
- 推荐仍是本地可解释规则。轻量资料覆盖 7 源，其余来源仍依赖列表和实际打开作品；全候选题材覆盖、缺失原因的持续统计及用户群效果评估尚未建立。本轮没有“准确率提升百分比”或模型训练结论。
- 已验证桌面 Chromium 的手机视口与 240 页逐页模式。真实 iOS/Android 的峰值内存、连续长图帧时间、长时间网络波动仍需要实际设备验证。
- 下一章预取、跨设备同步、OAuth、不同版本漫画自动迁移章节/页码等，仍是 README 中列明的后续功能。
- CI 工作流已纳入本地版本控制，远端运行结果尚不存在。
